# Mode A/B/C 差异分析：为什么模式C理论上最好但实践中感觉并非如此

## 1. 三种模式的核心差异

| 特性 | **模式A (传统遥操作)** | **模式B (固定增益)** | **模式C (本文方法)** |
|------|----------------------|---------------------|---------------------|
| 视觉语义 | ❌ 无YOLO | ✅ 有YOLO检测 | ✅ 有YOLO检测 |
| 力反馈 | **零力 (透明模式)** | **固定 K_trans=0.6** | **自适应 K_trans(c)** |
| 导纳刚度 | **固定 K=200 N/m** | **固定 K=200 N/m** | **自适应 K(c)** |
| 死区 | 无 | 固定 deadband=0.4N | 自适应 deadband(c) |
| 夹持力估计 | ✅ (仅监控) | ✅ (仅监控) | ✅ (接触脉冲) |

## 2. 自适应参数表 (来自 `vision_physics_mapper.py`)

| 物体 | label | 导纳刚度 K | K_trans (力反馈增益) | deadband | 理论目的 |

## 3. 深入分析：为什么模式C理论上最优但实践感受不佳

### 🔴 问题1: 力反馈增益自适应带来的"感知不连续性"

这是**最核心的问题**。

```
模式B (固定):  K_trans = 0.6  → 所有物体力反馈强度一致
模式C (自适应): 
  - 香蕉 → K_trans = 0.3 → 力反馈很弱
  - 书本 → K_trans = 1.0 → 力反馈很强
```

**矛盾点**: 软物体（香蕉）最需要精细的力觉反馈来避免捏坏，但模式C反而将力反馈增益降到了最低（0.3）。操作员在抓取香蕉时几乎感受不到接触力，这反而降低了操作精度。而在抓取硬物体时突然力反馈很强，可能让操作员感到突兀。

**建议**: 对软物体应该保持**中等偏上的力反馈增益**（如 0.5-0.7），让操作员能清晰感知接触，同时只降低导纳刚度来物理上限制冲击力。

### 🟠 问题2: 导纳刚度切换的"手感突变"

从代码 [`adaptive_admittance.py`](plans/adaptive_admittance.py:82-98):

```python
if profile.label == "soft":
    K_z = K_val * 0.5  # 软物 Z 轴再减半 → 25 N/m
elif profile.label == "hard":
    K_z = K_val         # 硬物 → 300 N/m
```

刚度从 300 N/m 切换到 50 N/m 是 **6倍的变化**。操作员会明显感觉机械臂突然变得"软塌塌的"，位置跟踪延迟增加。这会让操作员误以为系统不稳定或失控。

此外，阻尼系数也是随刚度自动计算的：
```
D = 2 · sqrt(M · K)   # M_eff = 3.0 kg
  → K=50  → D ≈ 24.5 N·s/m  (低阻尼)
  → K=300 → D ≈ 60.0 N·s/m  (高阻尼)
```

低刚度+低阻尼可能导致轻载状态下的**欠阻尼振荡**。

### 🟡 问题3: 视觉检测的可靠性与延迟

从 [`shared_control_node.py`](plans/shared_control_node.py:440-480) 可以看到视觉流程：
1. 摄像头 30fps 采集
2. RGB 帧入队到 `frame_queue`
3. YOLO 独立进程推理
4. 结果从 `result_queue` 返回
5. 主循环通过锁更新 `current_profile`

**问题点**:
- 如果 YOLO 检测不稳定（置信度波动、误检、漏检），profile 会在不同物体参数间频繁切换
- 5秒超时回退机制 ([`shared_control_node.py`](plans/shared_control_node.py:704-715))：当检测丢失 >5秒且 Omega 完全张开时，回退到默认 profile（K=100 N/m, K_trans=0.4）
- 如果用户操作较快（<5秒完成一次抓取），超时回退可能不会触发，但 profile 可能一直停留在上一次检测的物体上

### 🟢 问题4: 夹爪控制的"追赶模式"问题

从 [`shared_control_node.py`](plans/shared_control_node.py:834-885) 的夹爪控制逻辑：

```python
# 追赶模式: 始终记录最新目标
self._gripper_pending_width = target_width

# 当有显著变化时启动 worker
if width_change > GRIPPER_HYSTERESIS:
    if not self._gripper_busy:
        # 启动 worker
    else:
        # 仅更新 pending_width，不重复启动
```

这种设计的目的是不阻塞 200Hz 主循环，但带来以下问题：
- **夹爪动作滞后于操作员意图**
- 连续捏合/张开时，`grasp()` 被 fire-and-forget 后立即返回，实际的夹持力可能不够
- 对软物体尤其危险：夹爪闭合过快可能压坏物体，闭合过慢可能夹不住

### 🔵 问题5: 接触事件检测的"防抖"延迟

从 [`grip_force_estimator.py`](plans/grip_force_estimator.py:117-133):

```python
if width_stalled and not_at_max and torque_active:
    self._contact_frames += 1
    if self._contact_frames >= self.debounce_frames:  # 默认5帧
        # 触发接触事件
```

200Hz 控制循环 × 5帧防抖 = **25ms 延迟**。这对接触事件检测来说过长，操作员可能在感受到脉冲提示之前已经完成了夹持动作。

### 🟣 问题6: 实验数据中的问题

从已有的实验元数据看：

```
trial_002_modea_book_retry → result: retry, duration: 16.91s, rows: 0
trial_004_modea_book_retry → result: retry, duration: 63.51s, rows: 281
trial_001_modec_banana_failure → result: failure, duration: 77.3s, rows: 294
```

- **所有试验都是 "retry" 或 "failure"**，没有 "success"
- **rows=0** 表示数据采集器没有捕获到有效数据行（可能采集脚本或解析有问题）
- 模式C处理香蕉用了77秒仍失败——说明自适应策略没能帮助完成抓取

## 4. 模式B vs 模式C 的"反直觉"对比

| 维度 | 模式B (固定增益) | 模式C (自适应) | 为什么C可能更差 |
|------|-----------------|---------------|--------------|
| **操作一致性** | 手感始终一致 | 手感随物体变化 | 突变导致不适 |
| **力反馈强度** | 始终 0.6 | 0.3~1.0 波动 | 软物体反馈太弱 |
| **系统响应** | 刚度固定 200 N/m | 50~300 N/m 切换 | 软物体响应迟钝 |
| **鲁棒性** | 不依赖视觉 | 高度依赖视觉 | 视觉失败则性能下降 |
| **学习曲线** | 无需适应 | 需适应不同手感 | 操作员负担增加 |

## 5. 改进建议

### 5.1 力反馈增益调整 (优先级最高)
```
当前: 软物 K_trans=0.3 → 反馈太弱
建议: 软物 K_trans=0.6~0.7 (让操作员能清晰感知)
理由: 软物体更需要精细的力觉反馈
      反馈增益和导纳刚度是正交的两个维度
         - 导纳刚度低 → 物理上保护物体
         - 力反馈增益高 → 操作员感知清晰
```

### 5.2 导纳刚度渐变切换
```python
# 当前: 瞬间切换
self.ctrl.set_impedance(K_new)

# 建议: 线性插值过渡
for K_interp in np.linspace(K_old, K_new, num=50):
    self.ctrl.set_impedance(K_interp)
    time.sleep(0.01)  # 500ms 平滑过渡
```

### 5.3 视觉检测丢失时的"渐变回退"
```
当前: 检测丢失 → 保持5秒 → 立即回退默认
建议: 检测丢失 → 逐渐回归默认 (参数插值, 而非跳变)
```

### 5.4 夹爪控制增加力控模式
```
当前: 纯位置控制 (move/grasp)
建议: 软物体采用力控夹持模式
      gripper.grasp(target_width, speed, force=5.0)
      限制最大夹持力，避免压坏软物体
```

### 5.5 接触事件检测灵敏度优化
```
当前: 防抖5帧 (25ms)
建议: 防抖2帧 + 阈值动态调整
      根据物体label调整扭矩阈值:
        soft → torque_threshold = 0.5 Nm
        hard → torque_threshold = 1.5 Nm
```

## 6. 总结

| 问题 | 影响程度 | 修复难度 | 对论文的影响 |
|------|---------|---------|------------|
| 软物力反馈增益太低 | 🔴 高 | 低 (改参数) | 直接影响H3/H4假设验证 |
| 刚度切换不平滑 | 🔴 高 | 中 (加插值) | 影响用户体验和TLX评分 |
| 视觉检测延迟/不稳定 | 🟠 中 | 高 (系统性问题) | 影响所有假设 |
| 夹爪控制追赶模式 | 🟠 中 | 高 (需重构) | 影响抓取成功率 |
| 接触检测延迟 | 🟢 低 | 低 (调参数) | 影响力反馈品质 |

**最关键的问题**: 力反馈增益 K_trans 在软物体上设置得太低（0.3），这违背了"需要精细感知的物体应该给更强反馈"的人因工程学原则。修复这个参数后，模式C的性能应该会有明显提升。
